Chapter 00

Lit:
Web Components
that don't suck

Lit is a lightweight library (~5kb) built on top of the native Web Components standard. If you know React or Vue, the mental model translates — but Lit has zero virtual DOM overhead and ships real custom elements the browser natively understands.

🔥 lit-html

  • Tagged template literal renderer
  • Updates only changed parts (no vDOM diff)
  • Zero runtime abstraction
  • Works standalone — no component needed

🧩 LitElement

  • Base class extending HTMLElement
  • Reactive property system
  • Shadow DOM & scoped CSS
  • Lifecycle hooks you already know
Coming from React / Vue

Think of lit-html as JSX without a transpiler — it's just JavaScript template literals. LitElement is your component class — like a Vue SFC or a React class component, but compiled to a real browser custom element.

Mental model

Lit's update cycle: state change → schedule microtask → re-render changed bindings only. No reconciler, no virtual DOM, no fiber. The browser's built-in DOM is the ground truth.

The entire Lit mental model in 10 lines JS 
// lit-html: render a template into a container
import { html, render } from 'lit';

const template = (name) => html`<p>Hello, ${name}!</p>`;
render(template('Gus'), document.body);

// LitElement: a reusable custom element
class MyEl extends LitElement {
  static properties = { name: {} };
  render() { return html`<p>Hello, ${this.name}!</p>`; }
}
customElements.define('my-el', MyEl);

Chapter 01 · lit-html

Template
Basics

The html tag is a tagged template literal. It returns a TemplateResult — a description of DOM, not actual DOM. Lit caches the structure and only patches the dynamic parts on updates.

Binding types

There are 5 binding positions, each with a distinct syntax. Getting these right is the foundation of everything.

src/01-lit-html-basics/bindings.js JS 
import { html, render } from 'lit';

const active = true;
const label = 'Click me';
const count = 42;

const tpl = html`
  <!-- 1. TEXT binding: value interpolated as text node -->
  <p>${label}</p>

  <!-- 2. ATTRIBUTE binding: reflected as HTML attribute -->
  <input type="text" value=${count} />

  <!-- 3. BOOLEAN ATTRIBUTE: use ?attr= syntax -->
  <button ?disabled=${!active}>Submit</button>

  <!-- 4. PROPERTY binding: sets DOM property, not attr -->
  <input .value=${count} />

  <!-- 5. EVENT binding: adds event listener -->
  <button @click=${() => console.log('clicked')}>Click</button>
`;

render(tpl, document.querySelector('#app'));
Attribute vs Property

value=${x} sets the HTML attribute (string). .value=${x} sets the JS property (any type). For arrays, objects, and booleans — always use .prop or ?attr syntax.

Child templates & composition

src/01-lit-html-basics/composition.js JS 
// Nest TemplateResults — Lit handles it natively
const card = (title, body) => html`
  <div class="card">
    <h3>${title}</h3>
    <p>${body}</p>
  </div>
`;

// Arrays of TemplateResults render as a list
const items = ['Foo', 'Bar', 'Baz'];
const tpl = html`
  <ul>
    ${items.map((i) => html`<li>${i}</li>`)}
  </ul>
  ${card('Hello', 'World')}
`;

Conditional rendering

Ternary vs nothing JS 
import { html, nothing } from 'lit';

// Ternary — renders one of two things
html`${loggedIn ? html`<p>Welcome</p>` : html`<p>Login</p>`}`;

// nothing — renders absolutely nothing (no comment node)
html`${show ? html`<div>Visible</div>` : nothing}`;

// false, null, undefined also render nothing
html`${show && html`<div>Also works</div>`}`;
Chapter 02 · lit-html

Directives

Directives are special functions that customize how Lit renders a binding. They run during rendering and can hold state between renders — unlike plain expressions.

Built-in directives

src/02-directives/repeat.js — keyed list rendering JS 
import { html, render } from 'lit';
import { repeat } from 'lit/directives/repeat.js';

const items = [
  { id: 1, name: 'Alice' },
  { id: 2, name: 'Bob' },
];

// repeat(items, keyFn, templateFn)
// Key function is critical for efficient DOM reuse (like Vue :key)
const tpl = html`
  <ul>
    ${repeat(
      items,
      (item) => item.id,         // key fn
      (item) => html`<li>${item.name}</li>`
    )}
  </ul>
`;
src/02-directives/cache.js — avoid re-creating DOM JS 
import { cache } from 'lit/directives/cache.js';

// Without cache: DOM is destroyed/recreated on condition change
// With cache:    DOM is kept alive, just detached (like v-show)
html`${cache(tab === 'a' ? html`<tab-a></tab-a>` : html`<tab-b></tab-b>`)}`;
src/02-directives/classmap-stylemap.js JS 
import { classMap } from 'lit/directives/class-map.js';
import { styleMap } from 'lit/directives/style-map.js';

const classes = { active: true, disabled: false, highlight: isNew };
const styles = { color: 'red', fontSize: '14px' };

html`
  <div class=${classMap(classes)}>Styled div</div>
  <p style=${styleMap(styles)}>Inline styles</p>
`;
src/02-directives/live.js — syncing external state to inputs JS 
import { live } from 'lit/directives/live.js';

// Problem: .value= only sets if value changed since last render
// live() checks against the live DOM value, not the last rendered value
// Essential for controlled inputs driven by external state
html`<input .value=${live(this.value)} />`;

Custom directives

src/02-directives/custom-directive.js JS 
import { Directive, directive, PartType } from 'lit/directive.js';

// A directive that debounces an event handler
class DebounceDirective extends Directive {
  constructor(partInfo) {
    super(partInfo);
    if (partInfo.type !== PartType.EVENT)
      throw new Error('debounce() must be used on an event binding');
    this._timer = null;
  }

  render(handler, delay = 300) {
    return (e) => {
      clearTimeout(this._timer);
      this._timer = setTimeout(() => handler(e), delay);
    };
  }
}

const debounce = directive(DebounceDirective);

// Usage
html`<input @input=${debounce(this.onSearch, 400)} />`;
Chapter 03 · LitElement

Your First
LitElement

LitElement extends HTMLElement. When you define a property, Lit automatically schedules a re-render when it changes — batched into a single microtask.

src/03-lit-element-basics/counter-element.js JS 
import { LitElement, html, css } from 'lit';

class CounterElement extends LitElement {

  // 1. Declare reactive properties
  static properties = {
    count: { type: Number },
  };

  // 2. Initialize state in constructor
  constructor() {
    super();
    this.count = 0;
  }

  // 3. Scoped styles (live in Shadow DOM)
  static styles = css`
    :host { display: block; font-family: sans-serif; }
    button { padding: 8px 16px; cursor: pointer; }
    .count { font-size: 2rem; font-weight: bold; }
  `;

  // 4. Render — called automatically on property change
  render() {
    return html`
      <button @click=${() => this.count--}>−</button>
      <span class="count">${this.count}</span>
      <button @click=${() => this.count++}>+</button>
    `;
  }
}

customElements.define('counter-element', CounterElement);
Decorator syntax

With TypeScript and decorators enabled, you can use @customElement('counter-element') and @property({ type: Number }) instead of static fields. This tutorial uses static fields — no transpiler needed.

Internal vs reflected state

Internal state: @state() JS 
import { LitElement, html } from 'lit';

class MyEl extends LitElement {
  static properties = {
    // PUBLIC — settable from outside, reflects as attribute
    label: { type: String },

    // INTERNAL — like Vue's data() or React's useState
    // { state: true } means: don't reflect to attribute
    _open: { state: true },
  };

  constructor() {
    super();
    this.label = '';
    this._open = false;
  }
}
Chapter 04 · LitElement

Lifecycle

Lit's lifecycle is a superset of the native custom elements lifecycle. You get hooks for both DOM connection and reactive update cycles.

src/04-lifecycle/lifecycle-element.js — full annotated lifecycle JS 
class LifecycleEl extends LitElement {

  // ─── Native Custom Element lifecycle ────────────────────────────

  connectedCallback() {
    super.connectedCallback();  // always call super
    // Element added to DOM. Subscribe to stores, start timers, etc.
    this._sub = store.subscribe(this.onStoreUpdate);
  }

  disconnectedCallback() {
    super.disconnectedCallback();
    // Element removed from DOM. ALWAYS clean up subscriptions!
    this._sub.unsubscribe();
  }

  // ─── Lit reactive update lifecycle ──────────────────────────────

  willUpdate(changedProps) {
    // Called before render(). Compute derived state here.
    // changedProps: Map of { propName => oldValue }
    if (changedProps.has('items'))
      this._sorted = [...this.items].sort();
  }

  render() {
    return html`...`;
  }

  firstUpdated() {
    // Fires ONCE after first render. Use for focus, measurements, etc.
    this.shadowRoot.querySelector('input')?.focus();
  }

  updated(changedProps) {
    // After every render. Avoid triggering another render here
    // (causes infinite loops). Use for imperative DOM integration.
    if (changedProps.has('open') && this.open)
      this._animate();
  }

  // Wait for pending renders to settle
  async someAsyncAction() {
    this.loading = true;
    await this.updateComplete;  // Promise that resolves after render
    // Now safe to measure DOM, read computed styles, etc.
  }
}
willUpdate vs updated

willUpdate: sync, before render, safe to mutate state. updated: after render, for imperative DOM work. Never trigger reactive property changes inside updated() without a guard — you'll create an infinite loop.

Chapter 05 · LitElement

Reactive
Properties

Properties are the reactive data layer of LitElement. Understanding their options is what separates beginner from senior Lit work.

src/05-reactive-props/property-options.js — all options explained JS 
static properties = {
  type: converter used for attribute |  property reflection
  count: { type: Number },
  active: { type: Boolean },
  items: { type: Array },   // JSON.parse/stringify for attribute

  // attribute: false — prop not observable from HTML attribute
  _data: { attribute: false },

  // attribute: 'my-name' — custom attribute name (kebab-case)
  firstName: { type: String, attribute: 'first-name' },

  // reflect: true — mirrors property back to attribute (for CSS :attr selectors)
  selected: { type: Boolean, reflect: true },

  // state: true — internal reactive state, no attribute reflection
  _loading: { state: true },

  // hasChanged: custom equality check (skip render if unchanged)
  data: {
    type: Object,
    hasChanged(newVal, oldVal) {
      return newVal?.id !== oldVal?.id;
    },
  },
};

Mutating arrays & objects

Triggering re-render on mutable state JS 
// ❌ WON'T trigger render — same reference
this.items.push(newItem);

// ✅ New reference — triggers render
this.items = [...this.items, newItem];

// ✅ Or force update manually
this.items.push(newItem);
this.requestUpdate('items', prevItems);
Chapter 06 · LitElement

Styles &
Shadow DOM

Shadow DOM gives LitElement true style encapsulation. External CSS cannot leak in; internal CSS cannot leak out — except through CSS custom properties.

src/06-styles/styled-element.js JS 
import { LitElement, html, css, unsafeCSS } from 'lit';

class StyledEl extends LitElement {
  static styles = css`
    /* :host = the element itself */
    :host {
      display: block;
      padding: 16px;

      /* Expose CSS vars for theming from outside */
      color: var(--my-el-color, #333);
      background: var(--my-el-bg, white);
    }

    /* :host([attr]) — style host based on attribute */
    :host([selected]) { border: 2px solid blue; }
    :host([disabled]) { opacity: 0.5; pointer-events: none; }

    /* ::slotted — style projected slot content */
    ::slotted(p) { margin: 0; font-size: 14px; }

    /* :host-context — style based on ancestor (rare but useful) */
    :host-context(.dark-theme) { background: #1a1a1a; }
  `;

  render() {
    return html`
      <div>
        <slot name="header"></slot>  <!-- named slot -->
        <slot></slot>                <!-- default slot -->
      </div>
    `;
  }
}

Shared styles

src/06-styles/shared-styles.js JS 
// Define shared styles once as a CSSResult
export const typography = css`
  h1 { font-size: 2rem; line-height: 1.2; }
  p  { line-height: 1.6; }
`;

export const tokens = css`
  :host { --space-sm: 8px; --space-md: 16px; }
`;

// In your element: compose multiple stylesheets
class MyEl extends LitElement {
  static styles = [tokens, typography, css`
    .local { color: red; }
  `];
}
Adoptable Stylesheets

Lit uses Constructable Stylesheets (CSSStyleSheet) under the hood — styles are shared as a single object across all instances of a component, not duplicated. This is significantly more memory-efficient than injecting <style> tags.

Chapter 07 · LitElement

Events & Refs

Lit handles events declaratively in templates and gives you @query/@queryAll decorators (or shadowRoot.querySelector) for direct DOM access.

src/07-events/event-element.js JS 
class EventEl extends LitElement {

  // ─── Querying shadow DOM ─────────────────────────────────────────
  // Without decorators — use getter with shadowRoot
  get _input() {
    return this.shadowRoot.querySelector('input');
  }

  // ─── Dispatching events up ───────────────────────────────────────
  _onSubmit() {
    const val = this._input.value;

    // bubbles: true — event propagates through shadow DOM
    // composed: true — event crosses shadow DOM boundary
    this.dispatchEvent(new CustomEvent('my-submit', {
      detail: { value: val },
      bubbles: true,
      composed: true,
    }));
  }

  // ─── Event handler patterns ──────────────────────────────────────
  render() {
    return html`
      <input />

      <!-- Arrow fn: new fn each render (bad for perf on hot lists) -->
      <button @click=${() => this._onSubmit()}>Submit</button>

      <!-- Method reference: Lit binds automatically, no rebind -->
      <button @click=${this._onSubmit}>Submit</button>

      <!-- EventListener object: handleEvent pattern -->
      <button @click=${this}>Submit</button>
    `;
  }

  // The handleEvent pattern — single listener object
  handleEvent(e) {
    if (e.type === 'click') this._onSubmit();
  }
}
composed: true is crucial

Without composed: true, a CustomEvent dispatched from inside a shadow root will not bubble past the shadow boundary. Parent components listening with @my-event will never see it.

Chapter 08 · Advanced

Composition
Patterns

Lit offers two primary composition mechanisms beyond plain inheritance: Reactive Controllers (logic extraction) and Mixins (shared behavior across class hierarchies).

Reactive Controllers

Controllers are objects that hook into a host element's lifecycle. Think of them as composable lifecycle logic — the equivalent of Vue composables or React hooks.

src/08-composition/mouse-controller.js JS 
class MouseController {
  constructor(host) {
    this.host = host;
    this.pos = { x: 0, y: 0 };
    host.addController(this);  // register with host
  }

  // Controller lifecycle mirrors host lifecycle
  hostConnected() {
    window.addEventListener('mousemove', this);
  }
  hostDisconnected() {
    window.removeEventListener('mousemove', this);
  }
  handleEvent(e) {
    this.pos = { x: e.clientX, y: e.clientY };
    this.host.requestUpdate();  // trigger host re-render
  }
}

// Usage in any LitElement
class MyEl extends LitElement {
  mouse = new MouseController(this);
  render() {
    return html`X: ${this.mouse.pos.x}, Y: ${this.mouse.pos.y}`;
  }
}

Mixins

src/08-composition/disabled-mixin.js JS 
// Mixin: a function that takes a base class and returns a new class
const DisabledMixin = (Base) => class extends Base {
  static properties = {
    ...Base.properties,  // preserve existing props
    disabled: { type: Boolean, reflect: true },
  };

  constructor() {
    super();
    this.disabled = false;
  }
};

const FocusMixin = (Base) => class extends Base {
  focus() {
    this.shadowRoot.querySelector('[tabindex]')?.focus();
  }
};

// Compose multiple mixins
class MyButton extends FocusMixin(DisabledMixin(LitElement)) {
  render() {
    return html`<button ?disabled=${this.disabled}><slot></slot></button>`;
  }
}
Chapter 09 · Advanced

Context API

Context lets you pass data through the component tree without prop drilling — the Lit equivalent of React Context or Vue's provide/inject. It uses a DOM event-based protocol under the hood.

src/09-context/theme-context.js — define + provide JS 
import { createContext, provide, consume }
  from '@lit/context';

// 1. Define a typed context key
export const themeContext = createContext('theme');

// 2. Provider — high up in the tree
class AppRoot extends LitElement {
  static properties = {
    theme: {
      // The @provide decorator (static fields equivalent below)
      context: themeContext,
      type: Object,
    },
  };

  constructor() {
    super();
    // Any component that requests themeContext will receive this
    this.theme = { primary: 'blue', mode: 'dark' };
  }

  render() {
    return html`<slot></slot>`;
  }
}

// 3. Consumer — anywhere in the tree
class ThemedButton extends LitElement {
  static properties = {
    theme: { context: themeContext },
  };

  render() {
    return html`
      <button style="background: ${this.theme?.primary}">
        <slot></slot>
      </button>
    `;
  }
}
How context works

Consumers dispatch a context-request DOM event up the tree. The nearest provider intercepts it and calls the callback with the value. It uses no global state — it's pure DOM event bubbling. This means it works across frameworks too.
